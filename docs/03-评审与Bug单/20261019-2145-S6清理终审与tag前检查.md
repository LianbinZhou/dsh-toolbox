## 2. 发布前必须修的 5 件事

### 2.1 package-lock 版本

```text
package.json:       0.7.0
package-lock.json:  0.1.0（根包，以及 packages[""]）
```

这不是“只是元数据”：`npm ci`、`npm pack`、发布标签都可能以 lock 为准。  
要求：

```bash
npm install --package-lock-only
npm ci
npm test
```

确认 `package-lock.json` 根版本为 0.7.0，再继续。

### 2.2 S6 报告仍是 v0.6.0 / 44 文件

`06-S6封板报告.md` 当前：

```text
版本 v0.6.0
总计 44 个文件
```

索引当前：

```text
版本 v0.7.0
45 个文件
```

要求统一。建议 S6 报告改为：

```text
版本 v0.7.0
45 个内容文件（+ MANIFEST.sha256）
```

### 2.3 文件总数口径

实际磁盘：

```text
45 个内容文件 + 1 个 MANIFEST = 46 个文件
```

索引写“45 个文件”，报告写“44 个文件”，MANIFEST 有 45 条（不含自身）。  
要求明确写：

```text
45 个内容文件，另附 MANIFEST.sha256
```

否则下一次审计会再次对不上。

### 2.4 MANIFEST 行尾与校验

我实跑：

```bash
sha256sum -c MANIFEST.sha256
```

结果：

```text
WARNING: 45 listed files could not be read
```

原因是 MANIFEST 每行带 CRLF，文件名后多了 `\r`，Linux/Git Bash 无法匹配。

要求：

- 用 LF 重新生成；
- 在仓库/资料库根目录实跑 `sha256sum -c MANIFEST.sha256`，必须 45/45 OK；
- 如果 Windows 也要校验，提供 PowerShell 版本或说明使用 Git Bash；
- MANIFEST 不包含自身（否则自哈希无解），文件里注明。

### 2.5 权威关系与 06 的位置

索引写：

```text
仓库 docs/ 是唯一权威，本项目资料库是只读备份
```

但 `06-S6封板报告.md` 只在外部资料库，不在仓库 `docs/`。  
这会让“权威版本”缺最终结案报告。

要求二选一：

- 把 `06-S6封板报告.md` 复制进仓库 `docs/S6-封板报告.md`，再重新生成外部备份；
- 或修改索引，明确 S6 结案报告以外部资料库为准，并接受“权威不止一处”。

我建议 **把 S6 报告放进仓库 docs/，外部资料库仍做只读备份**。  
这样 README 链接、仓库浏览、外部归档三者一致。
