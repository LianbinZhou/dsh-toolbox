# S5 迁移执行计划：pluginZh 收进 toolbox + 卸载独立插件

> 拍板：老板（2026-10-18）——**全部迁进 toolbox，独立插件彻底卸载，开关必须真开真关**。
> 另一决策：`panelMenu` **继续留在容器**，不拆。

---

## 一、现状

| 项 | 情况 |
|---|---|
| `dsh-plugin-zh/client.js` | 16.4 KB 单文件 IIFE：`DICT` 28 条 + `MutationObserver` + 匹配规则 + 自证条 + `window.__DSH_PLUGIN_ZH__` |
| 匹配策略 | 文本节点空白归一化后**精确命中**；前 40 字符唯一命中容忍尾部截断 |
| 跳过 | `<code>/<pre>/<textarea>/<input>`；界面语言非中文时不工作 |
| **还原能力** | **没有**。直接改 `nodeValue`，原文丢失 → 关掉开关无法恢复英文 |
| toolbox 里的 `pluginZh` | **空开关**（只 `probe.bump` + `track`），拨了无任何效果 |

**结论**：迁移不是搬运，而是「搬运 + 补一个原插件没有的能力（可逆）」。
`archivePanel` 就是同类问题的先例——能开不能关的开关等于假开关。

---

## 二、目标（验收标准）

1. toolbox 的 `pluginZh` 开关是真功能：**开 → 汉化生效；关 → 英文原样回来**；
2. 独立插件 `dsh-plugin-zh` 从 web profile **彻底卸载**（`package.json` 依赖 + `node_modules` 链接）；
3. **不存在双重翻译**：同一页面不会有两个人改文本；
4. 字典与匹配逻辑**逐条等价**（28 条全部迁移，行为不变）；
5. 全量测试保持全绿（当前 410），并新增覆盖：开关双向、还原精确、重复挂载幂等、与 panelMenu 共存；
6. 真机：插件管理页开关拨动，文本在中文/英文间来回切换，无需刷新页面。

---

## 三、实施步骤

### 第 1 步：把翻译引擎搬进 `src/client/features/plugin-zh.js`

- 字典：`DICT` 原样搬为 `PLUGIN_ZH_DICT`（28 条，逐条对照，不删不改）；
- 匹配：`normalize()` + 精确/前 40 字符唯一命中，保持原逻辑；
- 观察器：`MutationObserver`（`subtree: true, childList: true, characterData: true`）；
- 跳过规则、语言判断、自证条文案一并搬；
- **新增可逆层**（原插件没有）：

```js
const applied = []   // [{ node, original }]
function translateNode(node) {
  if (node.__dshToolboxZh) return           // 已处理过，防重复
  const next = lookup(node.nodeValue)
  if (next === undefined) return
  applied.push({ node, original: node.nodeValue })
  node.nodeValue = next
  node.__dshToolboxZh = true
}
function restore() {
  for (const { node, original } of applied.splice(0)) {
    try { node.nodeValue = original; delete node.__dshToolboxZh } catch (e) {}
  }
}
```

- 只改**纯文本节点**的 `nodeValue`，不碰 React 节点、不写属性（与原插件同一策略）；
- `dispose()` = 断开 observer + `restore()`，保证「关掉就还原」。

### 第 2 步：接进容器（`features.js`）

- 把桩替换成真挂载：
```js
{ id: 'plugin-zh', configKey: 'pluginZh', reversible: true, title: '插件汉化',
  mount(ctx, env) { const handle = mountPluginZh(); env.track(() => handle.dispose()); probe.bump('plugin-zh') } }
```
- `reversible: true`（容器的热插拔契约要求：关掉必须能 dispose）。

### 第 3 步：卸载独立插件

1. 从 `~/.dsh/profiles/web/package.json` 的 `dependencies` 移除 `dsh-plugin-zh`；
2. 删除 `node_modules\dsh-plugin-zh` 链接；
3. `cordis.patch.yml` 里若有它的行，一并移除；
4. **保留仓库**（`dsh-plugins/dsh-plugin-zh`）不删，README 里标注「已并入 dsh-toolbox，仓库仅作历史」。

### 第 4 步：测试与真机

新增测试（`test/plugin-zh.test.mjs`）：
- 字典完整：28 条全部可命中；
- 匹配规则：精确 / 前 40 字符截断 / 不误伤（普通界面文字不被翻译）；
- **双向**：mount → 文本变中文；dispose → 文本恢复英文原文；
- **幂等**：重复 mount 不叠加 observer，不二次翻译；
- **共存**：与 panelMenu 同时挂载不互相干扰；
- **跳过**：`<code>` / `<pre>` 内的文本不动。

真机：插件管理页拨开关，中文 ↔ 英文来回切换，不刷新页面。

## 四、风险与对策

| 风险 | 对策 |
|---|---|
| 关掉后还原不完整（React 重渲染把新节点插进来） | `restore()` 只还原**记录过**的节点；新节点由 observer 断开后自然保持英文 |
| 与 `dsh-plugin-zh` 同时运行导致双重翻译 | 先卸载独立插件再开开关；测试里断言「只用一份 engine」 |
| 匹配误伤普通界面文字 | 沿用原策略：字典只收长句描述，精确匹配；测试覆盖「常见短文本不被翻译」 |
| 卸载插件后 profile 起不来 | 先改 `package.json` 再删链接；重启后看终端无 `pending` / 模块解析错误 |

---

## 五、顺序（不跳步）

1. 迁移引擎（可逆版）+ 单测 → 全绿；
2. 接进容器 `features.js`，桩替换成真挂载 → 全绿；
3. 卸载独立插件 → 重启验证 profile 正常；
4. 真机拨开关验证双向；
5. 更新 README（七开关中「插件说明汉化」改为真功能）、打 tag、推送。

---

## 六、不做什么

- 不改字典内容（除非发现错译）；
- 不做「按插件粒度的翻译开关」——一个总开关够了；
- 不碰 panelMenu（决策是继续留在容器，本轮不动）。
