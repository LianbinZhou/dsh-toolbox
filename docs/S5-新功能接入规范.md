# 新功能接入规范（S5 架构加固 · 任务一）

> 目标：**以后加新功能，只写一个文件 + 在 `features.js` 加一行配置**，
> 绝不改 `index.js` / `container.js` / `registry.js`（容器核心）。

---

## 一、三步接入

### 第 1 步：写一个独立文件 `src/client/features/<名字>.js`

```js
/**
 * <一句话说明这个功能做什么、关掉要还原什么>
 */

// 需要官方服务就过防腐层，别直接读 ctx.xxx
import { createDshAdapter } from '../dsh-adapter.js'

/**
 * 挂载。约定（由 registry.js 强制）：
 *   - 返回值可以是 void / disposer 函数 / { dispose() }；
 *   - 返回的东西会被容器 track，关掉开关时调用；
 *   - `reversible: true` 的含义是「关掉能完全撤销」。
 */
export function mount(ctx, env) {
  const dsh = createDshAdapter(ctx)

  // 官方服务缺失时只降级，不抛（否则整个容器崩）
  const sessions = dsh.get('sessions')
  if (!sessions) {
    console.warn('[dsh-toolbox] <名字>: sessions 不可用，本功能跳过')
    return
  }

  // 一切副作用都要能被撤销
  const timer = setInterval(() => {}, 1000)
  env.track(() => clearInterval(timer))

  return () => clearInterval(timer)   // 也可以直接 return，容器会 track
}
```

### 第 2 步：`features.js` 加一行配置

```js
{
  id: 'my-feature',            // 唯一
  configKey: 'myFeature',      // 唯一，对应设置卡片里的开关
  title: '我的功能',            // 卡片上显示的名字
  reversible: true,            // 关掉能不能完全还原
  mount: mountMyFeature,       // 上面写的 mount
},
```

同时在 `src/shared/switches.js` 的 `SWITCHES` 里加一条（决定卡片上展示的顺序与文案），
在 `src/host/config.js` 的 `shape` 里它会自动被 `SWITCH_KEYS` 带出来——**除非要非布尔字段**（那条要手写 schema，参考 `trashKeptDays`）。

### 第 3 步：写测试

最低三条：

1. **挂载后真的生效**（不是空壳）；
2. **关掉能还原**（`dispose` 后再断言状态回到原样）；
3. **官方服务缺失时不崩**（传一个只有 `slots` 的 ctx，断言 mount 不抛、只是跳过）。

## 二、硬性约束

| 约束 | 为什么 |
|---|---|
| **不许改 `index.js` / `container.js` / `registry.js`** | 那是容器核心。加功能改核心 = 每次都碰最高风险的文件 |
| **不许直接读 `ctx.<官方服务>`，一律走 `dsh-adapter.js`** | 官方一改接口就白屏。防腐层保证「缺了只降级」 |
| **`reversible` 必须如实声明** | 声明 `true` 却无法还原，关开关会留下残迹（S4 的删除残留就是这么来的） |
| **一切副作用交给 `env.track`** | 定时器、observer、slot 注册、patch 全要能撤 |
| **功能自检挂进 `window.__DSH_TOOLBOX__.selfCheck()`** | 真机排障先看它，不要从「白屏」猜起 |

## 三、官方 API 怎么用（防腐层 API）

```js
import { createDshAdapter, callOptional } from '../dsh-adapter.js'

const dsh = createDshAdapter(ctx)

dsh.get('sessions')        // 不存在或形状不对 → undefined（已警告，不抛）
dsh.require('slots')       // 必需服务缺失 → 明确抛错（让容器干净地失败）
dsh.selfCheck()            // { ok, missing[], degraded[], available[] }

await callOptional(sessions, 'refresh')   // 方法可能被官方改名：缺了就 undefined
```

已收口的服务：`slots` / `sessions` / `configForms` / `layout` / `locale`。
需要新的官方服务时：**先在 `dsh-adapter.js` 的 `SERVICE_CHECKS` 里加一条检查**，再在功能里 `dsh.get()`。

## 四、反例（这样写会被打回）

```js
// ✗ 直接读官方服务：官方改名就白屏
const sessions = ctx.sessions

// ✗ 不声明 reversible 却动了全局
mount() { document.body.style.background = 'red' }

// ✗ 加功能却去改容器核心
// （在 index.js 里手写 if (configKey === 'myFeature') ...）

// ✗ 定时器不 track：关掉开关后还在跑
setInterval(() => {}, 1000)
```
