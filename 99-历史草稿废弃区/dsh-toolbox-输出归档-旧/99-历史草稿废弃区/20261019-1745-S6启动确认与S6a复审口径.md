## 2. S6-a 代码审查清单

Harness 交付宿主 adapter 后，我会按以下条目审查：

### 2.1 行为不变

- S6-a **只做收口，不改删除/恢复/路由/开关行为**；
- 现有 433 测试必须保持全绿；
- `verify-trash` / `contract-check` 不回退；
- 宿主改动必须真重启验证，不能只看 HMR。

### 2.2 必需/可选的作用域

简报里的“必需”必须按**功能作用域**理解，不能把整个 host 插件变成必需：

| 服务 | 缺失时的正确行为 |
|---|---|
| `webServer` | 只让归档 HTTP 接口不挂；其余功能继续 |
| `workspaceRegistry` | 归档功能降级为只读/关闭；其余功能继续 |
| `sessions` | 判活失败关闭；不拖死其他功能 |
| `sessionQuery` | `session_search` 不注册；其余功能继续 |

不能出现：

```js
// 错：webServer 缺失时整个 dsh-toolbox host 不激活
const webServer = adapter.require('webServer')
```

正确做法是：adapter 在**归档 feature 的入口**里取，而不是在全局 `apply` 里 require。

### 2.3 自检端点安全

简报提到“挂到宿主日志 + 一个 `/debug` 端点”。审查时必须确认：

- 不新增未认证的 `/debug`；
- 如果要做端点，复用现有 token / Host / 同源守卫，或只写日志；
- 不返回 token、绝对路径、nonce、异常原文；
- 自检输出只包含服务名、missing/degraded、关键方法 typeof。

### 2.4 客户端 6 处

- `layout`：缺服务时点侧栏不切换，但插件不崩；
- `configForms`：缺服务时设置卡片显示不可用，不崩；
- 不碰 `slots` / `locale` 的必需路径；
- 补“缺 layout / 缺 configForms”两条测试。

### 2.5 失败关闭

- `sessions` 不可用时仍拒绝删除（不能因为 adapter 返回 undefined 就放行）；
- `workspaceRegistry` 不可用时归档只读/关闭；
- `sessionQuery` 晚到仍要能安装 `session_search`（S4 修过的时序不能回退）；
- 所有 adapter 缺失分支都不能抛到主流程。

### 2.6 交付证据

Harness 交付时请附：

- commit / diff；
- `npm test` 原始输出（433+，0 skip）；
- `scan-undefined` / `contract-check`；
- 真机重启后的 7 条路由注册日志；
- 缺失服务模拟的单元测试；
- `/debug`（如果实现）的鉴权证据。
