## 0. 结论

**规范方向可以批准；迁移执行计划不能按当前版本直接动工。**

架构方向是对的：

- 用 `dsh-adapter` 收口官方服务；
- 用 `features.js` 注册表保持零 index 改动；
- pluginZh 迁进容器并做可逆；
- 卸载独立插件，避免双翻译。

但有 **4 个必须先修的硬问题**：

1. **防腐层 `selfCheck()` 会假绿**，而且 `sessions` 被放进必选 `inject`，与“缺失只降级”矛盾；
2. **`features.js` 不是真正的一行注册**：pluginZh 的 mount 逻辑仍内联在 `features.js`，并直接读 `ctx.locale`，违反规范；
3. **可逆汉化的 `applied` 数组不安全**：节点被 React 销毁/复用会留下内存、还原可能覆盖新文本，同一个文本节点被 React 改回英文后不会重新翻译；
4. **卸载独立插件只改了 package.json 和软链，pnpm-lock 仍是旧的**；这会让 `pnpm install --frozen-lockfile` 或 DSH 升级失败/回装旧包。

## 1. 防腐层：思路对，但没“真防住”

### 1.1 做对的部分

`createDshAdapter` 的 `get()`：

- `ctx[name]` 和 `ctx.get(name)` 都包了 try/catch；
- 缺失/形状不匹配返回 `undefined`，不抛；
- 每个服务只警告一次；
- `callOptional()` 对缺失/抛错返回 `undefined`；
- `require('slots')` 缺失时明确抛错。

这些符合“可选服务降级、必需服务明确失败”的方向。

### 1.2 问题一：`selfCheck()` 会假绿

`createDshAdapter` 创建时并不探测服务，`missing/degraded` 只有第一次 `get()` 后才填。  
所以：

```js
const dsh = createDshAdapter({})
dsh.selfCheck()
```

实际返回：

```text
{ ok: true, missing: [], degraded: [], available: ['slots','sessions',...] }
```

**一个服务都没有，它却说全部可用。**  
这会让真机排障第一步就得到错误结论。

要求：

- `selfCheck()` 应该本身触发一次全量探测；或
- 在创建 adapter 时探测 `SERVICE_CHECKS` 中的所有服务；
- 补测试：空 ctx 的 `selfCheck()` 必须 `ok:false`，`missing` 包含所有服务。

### 1.3 问题二：`sessions` 被 inject 成必需服务

`src/client/index.js` 现在是：

```js
inject: ['slots', 'locale', 'sessions']
```

但规范说 `sessions` 是可选服务，缺失时应降级。  
把它放进根 `inject` 后，`sessions` 缺失会导致整个插件不激活——这与“只降级不崩”的目标矛盾。

要求二选一：

- `sessions` 改为 `ctx.inject(['sessions'], cb)` 可选等待；或
- 明确声明 `sessions` 是 web profile 的必需服务，并更新规范和自检。

### 1.4 问题三：规范说“所有官方访问走 adapter”，实际没有

当前仍直接读 `ctx` 的文件包括：

- `features.js` 的 pluginZh：`ctx.locale`；
- `archive-panel.js` 的 slots 注册；
- `panel-menu.js` 的 slots/layout/locale；
- `quote-reply.js` / `draft-notice.js` 的 locale/slots；
- `switches.js` 的 configForms；
- `form.js` / `index.js` 的 slots/configForms/locale。

`S5-第二步简报` 已经诚实写了“只收口 1 个服务，还剩 7 个文件/32 处”。  
所以：

- **规范可以作为“新功能必须遵守”的目标**；
- **不能对外说“防腐层已经覆盖全部官方访问”**；
- 如果要把规范作为硬约束，必须列出“存量豁免清单”，否则新 reviewer 会以为旧文件已合规。

### 1.5 问题四：`features.js` 不是一行注册

规范说“写一个文件 + `features.js` 加一行”。  
但当前 pluginZh 在 `features.js` 里有：

- 读 `ctx.locale` 的 10 行逻辑；
- `mountPluginZh()` 调用；
- `env.track`、`probe.bump`、`track`。

这不是“一行配置”，而是把功能逻辑又塞回了注册表。  
要求：

- `features.js` 只保留：

```js
{ id: 'plugin-zh', configKey: 'pluginZh', title: '插件汉化',
  reversible: true, mount: pluginZhMount }
```

- 语言判断、mountPluginZh、dispose 全部搬进 `src/client/features/plugin-zh.js`；
- plugin-zh 读取 locale 也走 adapter，而不是直接 `ctx.locale`。

## 2. 可逆汉化：当前 `applied` 方案不安全

### 2.1 当前实现

`plugin-zh.js` 现在是：

```js
const applied = []

if (node.__dshToolboxZh) return true   // 已处理，直接跳过
const raw = node.nodeValue
const zh = lookup(raw)
if (zh !== undefined) {
  applied.push({ node, original: raw })
  node.nodeValue = zh
  node.__dshToolboxZh = true
}
```

`restoreApplied`：

```js
for (const entry of applied.splice(0)) {
  entry.node.nodeValue = entry.original
  delete entry.node.__dshToolboxZh
}
```

### 2.2 问题 A：React 把同一个文本节点改回英文，不会重新翻译

我实测：

```text
翻译后 nodeValue = 中文
React 把同一个 node.nodeValue 改回英文
再次 translateTextNode -> 返回 true
但 nodeValue 仍是英文
```

原因：

```js
if (node.__dshToolboxZh) return true
```

标记还在，直接跳过了。

结果：开关明明是开的，插件页刷新/重渲染后英文又出现，直到页面重新挂载。

要求：

- 不能只看 marker；
- 必须保存 `{ node, original, translated }`；
- 如果 marker 存在但 `node.nodeValue !== translated`：
  - 说明 React 改写了这个节点；
  - 把当前值当作新的 `original`，重新查字典；
  - 不匹配就清掉 marker/entry。

### 2.3 问题 B：React 销毁节点后，`applied` 持有引用，内存无界增长

`applied` 是普通数组，保存所有翻译过的 DOM 节点。  
React 每次重渲染替换文本节点，旧节点已经脱离 DOM，但数组仍持有它。

长期停留在插件管理页，`applied` 会越来越大；  
`dispose()` 遍历这些 detached 节点，虽然 `nodeValue =` 通常不抛，但内存已经泄漏。

要求：

- 用 `Map<node, {original, translated}>` + 每轮 pass 清理 `!node.isConnected` 的条目；或
- 用 `WeakMap` 记录节点状态 + 一个 `Set` 管理当前连接节点（需要定期 prune）；
- 不能只用普通 array 永久持有所有节点。

### 2.4 问题 C：节点被复用后，restore 可能覆盖新文本

`restoreApplied` 只判断 `entry.node` 存在，就直接写 `original`。  
如果 React 把旧节点复用到另一个元素，或节点内容已经变了，`dispose()` 会把**当前新文本**覆盖成旧英文，造成页面内容错乱。

要求：

- 记录 `translated`；
- 还原前检查 `node.isConnected` 且 `node.nodeValue === translated`；
- 不满足就只清 marker，不写 `original`；
- 节点已 detached 则跳过。

### 2.5 问题 D：expando 标记没有 WeakMap 安全

`node.__dshToolboxZh` 是直接挂在 DOM 节点上的可枚举属性：

- 可能和宿主/其他插件冲突；
- 节点复用后标记语义不可信；
- 没有 WeakMap/WeakSet 的隔离。

要求：

- 用 `WeakMap` / `WeakSet` 管理节点状态；
- 如果必须用 expando，至少用 `Symbol.for('dsh-toolbox.zh')`，并配合 `translated` 值校验。

### 2.6 测试缺口

`test/plugin-zh.test.mjs` 目前只有纯函数测试：

- 字典 28 条；
- 精确/前缀匹配；
- 普通短文本；
- 纯对象节点的 restore；
- 重复翻译；
- code/pre 跳过；
- 非中文 mount 不抛。

**没有一条真实 DOM / React 重渲染测试。**  
必须在动工前补：

1. 同一文本节点被 React 改回英文 → 必须重新翻译；
2. 节点被替换 → 新节点翻译，旧记录被 prune；
3. 节点被复用 → dispose 不得覆盖新文本；
4. 1000 次重渲染后 `applied` 不随 detached 节点无界增长；
5. 开关开→关→开→关，无残留、无重复 observer；
6. 真浏览器（插件管理页）双向切换。

没有这些测试，`reversible: true` 不能算成立。

## 3. 卸载独立插件：lockfile 没处理，这是硬风险

### 3.1 当前实际状态

`~/.dsh/profiles/web/package.json`：

- 已没有 `dsh-plugin-zh` 依赖；
- 仍有 `dsh-toolbox` link。

`node_modules/dsh-plugin-zh`：

- 已不存在。

但 `~/.dsh/profiles/web/pnpm-lock.yaml` 仍有：

```yaml
dsh-plugin-zh:
  specifier: link:C:/.../dsh-plugin-zh
  version: link:...
```

`node_modules/.pnpm/lock.yaml` 里也仍能看到旧记录。

### 3.2 风险

下次执行：

```bash
pnpm install --frozen-lockfile
```

会因为 `package.json` 与 lockfile 不一致而失败。  
DSH 升级如果内部使用 frozen install，profile 就会起不来。  
如果执行普通 `pnpm install`，pnpm 可能重写 lock，但是否会重新安装旧包取决于 lock/虚拟 store 状态——不能赌。

### 3.3 要求

卸载步骤必须改成：

```bash
cd ~/.dsh/profiles/web
pnpm remove dsh-plugin-zh        # 让 pnpm 同时改 package.json + lock + node_modules
# 或手工改 package.json 后：
pnpm install                     # 更新 lock 和虚拟 store
pnpm install --frozen-lockfile   # 必须通过
```

并验证：

- `grep dsh-plugin-zh pnpm-lock.yaml` 为空；
- `node_modules/dsh-plugin-zh` 不存在；
- `pnpm list dsh-plugin-zh` 为空；
- 重启 DSH 无 pending/模块解析错误；
- 插件管理页只有 toolbox 的开关，不出现旧插件。

### 3.4 版本号也不一致

`S5-第二步简报` 写 **v0.5.1**，但 `dsh-toolbox/package.json` 仍是 **0.4.0**。  
S5 封板前必须统一，否则 tag、npm pack、profile 显示会互相矛盾。

## 5. 我的批准意见

### `S5-新功能接入规范.md`

**批准作为设计规范/目标。**

但加一条：

> 存量 7 个文件/32 处未收口属于已知豁免，新功能必须遵守；不能把“规范已写”当成“存量已合规”。

同时把“features.js 只加一行”修正为：

> 功能逻辑必须在独立文件；`features.js` 只允许 import + 一条配置。

### `S5-迁移执行计划.md`

**有条件批准，不能按当前版本直接动工。**

必须先完成：

1. 可逆层改为 Map/WeakMap + prune + `translated` 校验；
2. 补 React 同节点改写 / 节点替换 / 节点复用 / detached 内存测试；
3. `features.js` 的 pluginZh 逻辑搬回 `plugin-zh.js`，走 adapter，不直接读 `ctx.locale`；
4. `selfCheck()` 改为真实探测，空 ctx 不得假绿；
5. 明确 `sessions` 是可选还是必需，修正 root `inject`；
6. `pnpm remove dsh-plugin-zh` + `pnpm install` + `pnpm install --frozen-lockfile` 验证；
7. 统一 package 版本与 S5 简报版本。

这 7 条补完，再动工/合并。  
在此之前，**不要删除独立插件**，否则会把一个可回滚的迁移变成 profile 起不来的事故。
