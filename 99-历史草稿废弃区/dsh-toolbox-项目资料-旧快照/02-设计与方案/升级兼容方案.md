# DSH 升级与 dsh-toolbox 兼容方案

> 适用：dsh-toolbox 0.1.0，DSH 0.2.1-rc.2 起。
> 目的：DSH 每次升级后，用**可执行的方式**确认插件没坏，而不是凭感觉。

---

## 一、升级后的三步体检

```powershell
# 1. 确认宿主的真实版本（不是文件版本，是正在跑的）
node tools/contract-check.mjs

# 2. 插件自己的测试（纯逻辑，不依赖宿主）
npm test

# 3. 浏览器里看面板
#    Ctrl+F5 → 「历史归档」→ 能列出会话 = 客户端契约没变
```

`contract-check.mjs` 检查 5 项，任何一项失败都会以退出码 1 结束：

| 检查项 | 期望 | 它证明什么 |
|---|---|---|
| 凭证端点可用 | 200 + `no-store` + 64 位令牌 | `webServer.register` 契约还在 |
| 列表可读（带令牌） | 200 + 行数 | `workspaceRegistry.archivedSessionIds` 与本地服务链路还在 |
| 列表拒绝无令牌 | 401 | 鉴权没被绕过 |
| 伪造 Host 被拒 | 403 | Host 白名单还在（裸请求，不是 fetch） |
| 参数校验生效 | 400 | 请求体校验还在 |

## 二、已经踩过的契约差异（记录在案）

### 1. `webServer` 的路由不再有 `method` 字段

- 0.2.1-alpha.4：注册路由时带 `method: 'GET' | 'POST'`，不带就匹配不上、落到宿主兜底并返回纯文本 401。
- 0.2.1-rc.2：`WebRoute` 类型只剩 `{ kind, path, handler }`，没有 `method`。

**我们的应对**：每个 handler **自己**校验方法（token 只认 GET、list 只认 GET、delete/unarchive 走 guard 的 `methods: ['POST']`）。
所以即使 `method` 被忽略，行为仍正确——**这是实测通过的，不是推断**（rc.2 下 list 200、坏 id 400、伪造 Host 403）。

### 2. `inject` 只支持数组

`inject: { required: [...], optional: [...] }` 会被当成「等待名为 required 和 optional 的两个服务」，插件永远 pending。
必须写 `inject: ['tools']`，可选服务用 `ctx.inject([...], cb)` 等。

### 3. `ctx.get(服务名)` 对未申报的服务返回 undefined

即使服务真实存在。要用 `ctx.inject(deps, cb)` 在作用域里取。

### 4. 客户端槽位有两套字段

- 主面板：`slots.register({ name: 'main', key: PANEL_ID }, 组件)`
- 侧栏列表：`slots.register({ name: 'sidebar.panellist', id: PANEL_ID, order, label }, 组件)`
- 两者都要 `ctx.slots.inject(SLOT, () => ...)` 包起来。

写错的表现：`layout.selectPanel: main panel "..." is not registered` 或 `list slot "..." requires options.id`。

## 二·补、已知现象（不是 bug，别乱改代码）

### 「全部面板」入口消失

**现象**：侧栏底部的「全部面板」按钮不见了，于是那些被收纳的原生面板（官方插件管理 / 技能中心 / 自动化任务 / 记忆系统）也一起看不见。

**原因**：DSH 会在侧栏底部推送一次性通知（例如 0.2.1-rc.2 的「模型已更新至 V4.1-Flash-1017，立即体验」）。它占据的正是 `sidebar.footer.action` 这一段，通知出现时会把同区域的收纳按钮挤掉。

**判断方法**（不用翻代码）：

1. 看侧栏底部是否有一条可关闭的通知卡片；
2. 控制台执行 `window.__DSH_TOOLBOX__.mounts('panel-menu')`，返回非 0 说明面板收纳本身挂上了；
3. 通知关掉后按钮自动回来 = 就是这个原因。

**结论**：**不要为了这个现象去改 panel-menu 的注册**。先关通知。

## 三、给后续版本定的规矩

1. **不赌版本号，只认体检结果**。版本号相同也可能改契约；`contract-check.mjs` 失败就是不能升级。
2. **插件不声明 `peerDependencies.@deepseek-ai/dsh`**。声明它会让 profile 的安装/重载多一层校验，写错范围反而让插件装不上；契约体检比版本范围更真实。
3. **任何宿主侧改动都必须真重启后再验证**（HMR 对宿主半边不可靠）。
4. **客户端改动只需 Ctrl+F5**，但要确认 `window.__DSH_TOOLBOX_ARCHIVE__` 存在、且 `apiEnabled()` 与开关一致。
5. **升级前备份 profile**：
   ```powershell
   Copy-Item ~/.dsh/profiles/web/cordis.patch.yml ~/.dsh/profiles/web/backup-$(Get-Date -f yyyyMMdd)
   ```
6. **升级后如果面板进不去**：先看浏览器控制台 `[dsh-toolbox]` 开头的报错，再跑体检脚本。两者能区分「宿主契约变了」和「客户端槽位变了」。

## 四、回滚

```powershell
# 降回上一个能用版本
npm i -g @deepseek-ai/dsh@0.2.1-alpha.4
# 恢复配置（如果有改动）
Copy-Item ~/.dsh/profiles/web/backup-20261018-before-rc2/* ~/.dsh/profiles/web/ -Force
```

回滚后**必须重启** DSH（`dsh` 进程加载的是启动时的引擎）。

## 五、桌面版说明

桌面版（Electron）**自带引擎**，不能用 `npm i -g` 升级：

- 版本看法：`DeepSeek Harness.exe` 的文件属性 → 当前 **0.2.0-rc.2**
- 升级方式：应用内「检查更新」，更新源 `https://download.deepseek.com/dsh-desk/feeds/win-x64/`（nightly 通道）
- **桌面 profile 没有装 dsh-toolbox**（装的是旧插件 `@local/dsh-session-search`、`dsh-quote-reply`），所以桌面版升级**不影响 toolbox**
- 若以后要把 toolbox 装进桌面 profile：只能用插件管理页的 `install_bundle`（CLI 会被拒绝，报 profile 被 Electron 独占）
