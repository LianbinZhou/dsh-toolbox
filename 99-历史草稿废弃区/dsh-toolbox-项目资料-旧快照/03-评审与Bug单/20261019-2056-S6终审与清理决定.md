## 2. docs/ 与项目资料库：建议“仓库权威 + 外部只读备份”

不建议只留一份后靠记忆保持同步。建议：

```text
仓库 docs/                  = 权威源，随代码提交、随 README 链接
dsh-toolbox-项目资料/       = 只读归档/备份，不手工编辑
```

理由：

- README 和代码里的链接指向仓库 `docs/`；删掉仓库 docs 会断链；
- 外部资料库包含 Pi 的 12 份历史评审和旧方案，不适合全部塞进源码仓库，但也不能丢；
- 两边都“可编辑”一定会漂移，必须指定唯一写入口。

执行要求：

1. 在 `00-项目资料总索引.md` 顶部明确写：
   - 仓库 `docs/` 是权威版本；
   - 本资料库是只读快照，修改必须先改仓库 docs，再重新生成归档；
2. 外部资料库加一份 `MANIFEST.sha256`（文件哈希），用于发现漂移；
3. 不要把项目资料库做成“仓库精简版”再反向同步——那会制造第二权威。

如果老板坚持只留一份：**留仓库 `docs/`**，外部资料库压成 zip/tar 备份，不参与日常编辑。
