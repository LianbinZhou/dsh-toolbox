## 一、项目一句话

插件页原来有 7 个自建插件的入口，装多了以后列表被自己的东西塞满。
这个项目把它们收成**一行**——点进去是一张 7 开关的设置卡片，每个开关实时生效、关掉能完全还原。

```
装之前：7 个插件行
装之后：1 个插件行（dsh-toolbox）→ 点进去 → 7 个开关
```

7 个开关当前全部是真功能：

| 开关 | 功能 | 阶段 |
|---|---|---|
| `sessionSearch` | `session_search` 工具 + 接管全文索引 seam | S2 |
| `quoteReply` | 划词引用 | S2 |
| `draftSaver` | 草稿保险箱 | S3 |
| `panelMenu` | 面板收纳 | S4 |
| `archivePanel` | 历史归档 + 回收箱 | S4 |
| `archiveHttpApi` | 归档 HTTP 接口（默认关闭） | S4 |
| `pluginZh` | 插件说明汉化（可逆） | S5 |

## 四、各阶段封板要点（只看这一节也够）

### S1–S3（铺垫）

容器骨架 + 前三个功能（会话搜索、划词引用、草稿保险箱）。
关键决策：**Config 是整对象 `.volatile()`**；开关是**实时热插拔**，关掉真 dispose。

### S4（历史归档 + 回收箱）

**状态机**：

```
Active → Archived → Trashed → Cleaned → Purged
          ↑            │
          └── 恢复 ─────┘
```

**四条不变量**（每次操作后都必须成立）：

1. 同一会话不能同时出现在回收箱和侧栏；
2. `dir-absent` 时不造行（目录没了就只清标记，绝不往工作区塞记录）；
3. `purge` 前必须先 cleanup（清不掉就拒绝，宁可留着也不留幽灵）；
4. 恢复要回原位置（删除前快照 `workspaceId / sessionId / beforeSessionId`）。

**修掉的 10 个真实缺陷**见 `S4-封板简报.md` 第三节（死锁、幽灵、未分组、isLive、参数名、双拼写…）。

**已知限制**：删除瞬间「未分组」闪现 <1 秒（数据 100% 安全，纯渲染层）。
两阶段删除方案评估后**不做**（为一个视觉边界引入新接口 + 新中间态，不划算）。

### S5（架构加固 + 汉化迁移）

**防腐层**：`src/client/dsh-adapter.js` + `src/host/dsh-adapter.js`

```js
get(name)        // 缺服务/形状不对 → undefined，只警告一次，绝不抛
require(name)    // 必需服务缺失 → 明确抛错
selfCheck()      // 每次真实探测，空环境必须报红
callOptional()   // 方法被官方改名 → 返回 undefined
```

**接入规范**：新功能 = 一个独立文件 + `features.js` 一行配置，不改容器核心。

**汉化迁移**：28 条字典 + MutationObserver 从独立插件迁入，**新增可逆层**：

```js
Map<node, {original, translated}>   // 记原文
pruneApplied()                       // 每轮清掉脱离 DOM 的记录
还原前三重校验                        // isConnected / nodeValue === translated
```

旧插件 `dsh-plugin-zh` 已从 web profile 彻底卸载（含 `pnpm-lock.yaml`）。

### S6-a（宿主防腐层 + 同步修复）

- 宿主 4 服务收口：`webServer` / `workspaceRegistry` 必需，`sessions` / `sessionQuery` 可选
- 客户端收口：`layout` 4 处、`configForms` 2 处（`slots`/`locale` 25 处明确豁免）
- 修掉的真 bug：
  - `scrubCache` 漏导入 `unlinkSync` → projcache 一直没删净
  - `scrubCache` 删了标题快照 → 恢复后显示「未命名」
  - `heal` 把 `cleaned` 当待办 → 每次启动空转（真机日志那串 `(60→60)`）
  - 面板不跟随左侧「归档」→ 改 2 秒轮询（隐藏暂停 / 卸载清理 / diff 才重渲染）

## 五、必须知道的坑（血泪清单）

| # | 坑 | 教训 |
|---|---|---|
| 1 | `withLock` 不可重入 | 锁内调带锁函数 = 永久挂起。拆 `restoreLocked` |
| 2 | `WorkspaceEntity.sessionIds` 是 **filtered getter** | 目录移走就"消失"；要读 `entity.record.sessionIds` |
| 3 | 「未分组」不是实体 | = `sessions.list` 减去各工作区成员 |
| 4 | 删目录后必须 `sessions.refresh()` | 否则侧栏不消失 |
| 5 | 重启 ≠ 刷新 | 客户端改动 **Ctrl+F5** 即可；宿主改动才要重启 |
| 6 | `Math.ceil` 显示天数 | 13.9 天会显示 14；应该 `Math.floor` |
| 7 | `applied` 数组存节点 | React 复用节点会覆盖新文本；必须用 Map + `translated` 校验 |
| 8 | 假自检 | 不探测就返回 `ok:true` 的自检会骗死排障 |
| 9 | `sessions.list` 订阅监听不到归档 | 归档状态在宿主 `workspaceRegistry`，只能轮询 |
| 10 | 幂等假象 | `detachSession ok (60→60)` 数量没变 = 行本来就不在，别被"成功"骗 |
